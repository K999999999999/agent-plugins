# Wizard

Wizard（交互式向导）是一个一次性 Bash 脚本，用来逐步引导用户完成 AI 无法代替的人工操作。它适合账号后台、凭证获取、手工迁移、访问授权和需要用户确认的切换步骤。

不要用它包装 Agent 可以自己完成的普通代码、测试或本地文件操作。

## 默认边界

向导默认是临时产物：

- 保存到 `.scratch/`、临时目录或项目约定的 `scripts/`；
- 完成一次流程后不自动保留或提交；
- 用户明确需要重复使用时，才将它作为普通工程变更进入 Spec / Ticket / Review；
- 不创建外部 Issue、PR 或远程任务。

向导只能把用户主动输入的配置写入本地安全位置，默认是 `.env`：

- 使用 `ask_secret` 隐藏读取敏感值；
- 使用 `write_env` 写入本地 `.env`；
- 不在终端、日志、Markdown、Commit 或汇总中打印敏感值；
- 不写入 GitHub Secret、CI Secret、远程变量或其他外部凭证库；
- `.env` 必须遵守仓库的 Secret 规则，不得提交到 Git。

## 流程

### 1. 确定人工步骤

先读取仓库事实，不要冷启动询问：

- `.env`、`.env.example`、`.env.*`；
- `README`、本地配置说明和运行文档；
- `docker-compose*`、Framework 配置和启动说明；
- 当前状态、目标状态以及中间不可逆动作；
- 用户本人必须完成的访问、复制、确认或后台操作。

不要读取或展示真实 Secret 的值。只确认变量名称、来源、是否必填和写入位置。

列出有序 Stage，以及每个 Stage 产生的值或状态。向用户确认后再编写脚本；用户可以增加、删除或调整顺序。

每个捕获值都必须明确：

- 用户从哪里得到；
- 写入本地哪个位置，或不写入任何位置；
- 是 Secret 还是公开值；
- 是否可以在重复运行时复用已有值。

### 2. 描述每个 Stage 的路径

每个 Stage 写出陌生用户可以执行的具体路径：

- 要打开的 URL 或本地页面；
- 需要点击、复制或确认的内容；
- 值出现在哪里；
- 它填充哪个变量；
- 完成后如何判断成功。

不知道当前页面、按钮或命令时，先查阅可信文档或向用户确认，不要编造可能已经变化的操作路径。

### 3. 编写向导

复制 [template.sh](template.sh) 到目标路径，只编辑 `STAGES` 标记之后的 Stage 区域：

- 一个 Stage 只做一个聚焦任务；
- 设置 `TOTAL_STAGES` 与实际 Stage 数量一致；
- 用 `stage`、`say`、`step`、`note`、`warn`、`open_url`、`ask`、`ask_secret`、`write_env`、`pause` 和 `confirm`；
- 打开页面后再询问用户复制值；
- Secret 使用 `ask_secret`；
- 所有需要持久化的本地值使用 `write_env`；
- 不添加外部 Secret 写入函数；
- 不修改模板中 `STAGES` 以上的向导库；
- 任何不可逆动作前使用 `confirm`。

### 4. 验证和交付

执行：

- `bash -n <script>`；
- 如果可用，运行 `shellcheck`；
- 检查脚本权限和目标路径；
- 静态追踪每个 Stage 的输入是否写入它声明的位置；
- 检查 Secret 没有被 `say`、`note`、`warn` 或 `finish` 打印。

不要自己端到端运行向导：它会打开浏览器并等待人工输入。只做静态检查，或在明确隔离环境中验证不包含敏感值的非交互部分。

告诉用户如何运行、如何停止、哪些值会写入本地 `.env`，以及如何安全地检查结果。不要自动 Commit；若用户明确要求把它变成可重复的项目能力，再进入标准实现和 Review 流程。

## 向导完成条件

- 每个用户必须完成的 Stage 都已命名并排序；
- 每个输入值的来源、类型和写入位置清楚；
- Secret 使用隐藏输入并且不会显示在汇总中；
- 重复运行不会无意破坏已有配置；
- 不可逆动作有确认门槛；
- 脚本通过语法检查；
- 没有外部 Secret、Issue、PR 或远程任务写入；
- 用户知道运行方式和失败后的恢复方式。

默认使用中文。命令名、环境变量名、API、文件路径、代码和必要的原始术语保持原样。
