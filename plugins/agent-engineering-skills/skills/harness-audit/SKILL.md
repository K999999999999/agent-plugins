# Harness Engineering Audit（工程 Harness 审计）

判断项目用于支撑 AI 工程任务的规则、上下文、状态记录、文档、工具、测试、CI 和反馈机制能否持续有效。覆盖任务启动、阶段转换、跨会话恢复、代码与文档同步、验证与交付以及 Harness 自身维护。目标是保持正确性、安全性、可靠性和可维护性，阻止缺少充分证据的高风险自动合并，并降低不必要的流程、测试和 LLM 成本；不承诺零 Bug。

## 唯一入口与边界

手动调用 `$harness-audit` 即开始全面审计。在当前目录用 `git rev-parse --show-toplevel` 定位仓库；未处于 Git 仓库时请求路径，不猜测目标。仅有一种全面审计模式，无须用户补充参数。领域优先级可调整，但不得把专项或抽样结果写成全面审计完成。

本 Skill 原名 `engineering-process-audit`，更名后仅保留当前入口。项目专用事实源、状态约定、命令、阈值和授权规则由目标仓库维护；先发现并复用已有机制，不将它们复制为通用 Skill 的固定要求，也不因缺少某个特定文件或工具就判定有缺陷。

默认只读：不修改代码、配置、GitHub 权限或分支保护，不提交、Push、创建 PR、合并、部署或自动实施改造；不调用付费模型，不触发付费 Eval 或破坏性操作。报告在会话中输出，必要的临时证据放仓库外并告知位置。不得输出密钥或业务敏感数据。

读取脚本的副作用后，才决定是否执行现有检查；不擅自安装依赖、运行可能写工作区或连接真实环境的测试、重跑远端工作流。默认依靠静态检查及已有运行记录；阻断能力需要实验时提出隔离验证方案，未经明确授权不得修改门禁或向真实分支注入失败。无法读取或验证不等于不存在。

## 全面审计流程

1. **建立基线与证据清单**：记录时间、根目录、HEAD、分支、工作区状态与远端。读取适用的 `AGENTS.md`、本地 Skill、需求 / Spec / Ticket、规范、脚本、测试 / Eval 配置、CI/CD 及相关 Git 历史。用 Git 文件清单结合隐藏目录和未跟踪配置定位流程资产，保护用户改动。区分已提交配置和当前未提交配置，不把后者当成远端生效配置。
2. **还原流程与全面覆盖**：按 [audit-checklist.md](references/audit-checklist.md) 覆盖全部 15 个领域，追踪需求 → 实施 → 验证 → Review → 合并 → 构建部署 → 观察恢复 → 回归反馈，并核对阶段转换、会话恢复、Living Documentation 和 Harness 自身维护。为每个阶段标明输入、产出、执行者、权限、门禁、失败行为和证据；不适用项说明项目事实依据。
3. **核验门禁可信度**：区分机械性规则、设计性判断和高风险决策，分别考察可执行检查、明确规范与 Review、明确授权或人工确认。Prompt、Skill、AGENTS.md 中的文字不能当作强制门禁。核对本地 / CI / Eval 验证语义、门禁自身的修改权限及自动合并资格；CI 全绿不能直接证明门禁有效。
4. **核对真实执行**：若已有 GitHub 只读访问，按 [evidence-and-github.md](references/evidence-and-github.md) 检查生效 Rulesets、分支保护、Required Checks、PR、Reviews、Checks 和工作流历史。没有访问能力时继续本地审计，准确标注远端未验证；不要求用户为完成本地审计先调整权限。追踪关键成功、失败、跳过和门禁变更记录，核对证据对应的 Commit、目标分支与配置版本。
5. **确认问题与成本收益**：追查候选问题的触发条件、现有保护和反证，合并相同根因。识别重复流程、过度审批、低价值测试和 Eval 成本；简化建议须说明保留哪些风险覆盖。错误反馈优先转成确定性测试、结构规则、契约或工具改进，不默认增加 Skill、审批阶段或独立系统。
6. **形成结论**：按 [report-template.md](references/report-template.md) 输出全部十项内容，给出 P0–P3 问题、三类改进结论及适用的自动合并就绪判断。交付前复核基线，发生变更则复核受影响结论。覆盖未闭合时写明“审计尚未完成”、待查项与原因；不得把跨快照结果拼成完整证据。

## 证据纪律

每项结论分别标注“文档声称存在 / 配置定义存在 / 实际被强制执行 / 有历史运行证据 / 已验证阻断能力”，记录各项是否成立及来源，不能自动逐级推断。问题另标已确认、疑似或未验证；保留权限不足、历史缺失、环境限制和反证。

静态配置足以证明的缺陷可以确认，但不得声称已运行复现。历史通过、本次通过、Mock 通过及真实目标链路通过分别记录。未执行、INVALID、环境错误、跳过或旧 Commit 的成功不得记作当前通过。没有某种工具、测试类型或文档本身不必然构成缺陷；依据实际风险判断，不以绿色检查、用例或 Skill 数量评判成熟度。

## 与其他 Skill 的边界

- `project-audit`：审计代码和项目产物的实际质量；本 Skill 审计支撑 AI 工程任务的 Harness 及其实际执行。
- `workflow-code-review`：审查某次具体变更；本 Skill 可读取历史 Review 评估机制有效性。
- `maintainability-refactor`：实施已确认问题的局部重构；本 Skill 只提出最小改进建议。

不自动调用这些 Skill，不依赖其他 Plugin 完成审计。默认以中文报告。
