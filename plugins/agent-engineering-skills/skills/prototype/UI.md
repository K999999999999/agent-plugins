# UI Prototype（界面原型）

UI Prototype 用同一条页面路径展示多个结构明显不同的界面方案。用户可以切换、比较并选择一个方案，或组合不同方案的优点，然后丢弃剩余变体。

如果问题是逻辑或状态模型，而不是视觉和交互结构，使用 [LOGIC.md](LOGIC.md)。

## 适用问题

- 页面应该采用哪种信息层级；
- 多个布局方案哪个更容易理解；
- 某个操作入口放在哪里最自然；
- 现有页面加入一块新内容后，整体结构是否仍然清楚。

## 页面位置

优先把变体挂在相关的现有页面上：

- 保留现有页面的数据、参数和权限逻辑；
- 只替换需要比较的渲染区域；
- 使用 `?variant=` 选择变体；
- 让用户在真实页面密度和上下文中判断，而不是在孤立空页面中判断。

只有没有合理宿主页面时，才创建临时 Prototype 路由，并在路径或文件名中明确标记 `prototype`。

## 流程

### 1. 写出问题并确定数量

默认制作 3 个变体，最多 5 个。先写出一句话：

> 在现有页面的同一路径上，用 `?variant=` 比较 3 种结构不同的方案。

方案数量过多会变成噪音，不能帮助用户做出判断。

### 2. 设计真正不同的变体

每个变体必须在结构、信息层级和主要操作入口上有明显差异：

- 不要只换颜色、间距或文案；
- 不要制作三个略有差异的 Card Grid；
- 尊重页面已有数据、权限和 Component Library；
- 每个变体拥有清晰的名称；
- 共享基础元素可以，但共享完整 Layout 会削弱比较价值。

### 3. 接入变体切换

使用项目现有 Router 和 URL Search Param：

```tsx
const variant = searchParams.get("variant") ?? "A";

return (
  <>
    {variant === "A" && <VariantA {...data} />}
    {variant === "B" && <VariantB {...data} />}
    {variant === "C" && <VariantC {...data} />}
    <PrototypeSwitcher variants={["A", "B", "C"]} current={variant} />
  </>
);
```

切换器应：

- 显示当前变体和名称；
- 支持前后切换并循环；
- 更新 URL，保证刷新和分享后仍保持当前变体；
- 支持键盘左右方向键；
- 输入框、文本区域或可编辑元素聚焦时不拦截方向键；
- 与被评估页面视觉区分；
- 在生产构建中隐藏，避免临时切换器进入用户界面。

### 4. 保持原型临时性

默认只读展示。需要修改数据时使用 Stub 或本地内存状态，不连接真实写入路径。不要为了原型补齐生产级错误处理、持久化和测试体系。

### 5. 交付和记录

交给用户页面路径和 `?variant=` 取值，让用户比较方案。记录最终选择、选择理由以及从其他变体借用的部分。

选定方案后：

- 将决定写入本地 Spec；
- 由 `implement` 按生产标准重新实现；
- 只保留经过确认的设计决定；
- 其余变体和切换器留在临时位置或由创建者清理；
- 不自动创建外部 Issue / PR，不把原型代码直接合入生产实现。

## 反模式

- 变体只差颜色或文案；
- 三个变体共享同一个完整 Layout；
- 原型直接连接真实写入操作；
- 把临时变体直接提升为生产代码；
- 在没有合理宿主页面时随意新增顶层路由；
- 让 Prototype 变成没有明确问题的半成品 Feature。
