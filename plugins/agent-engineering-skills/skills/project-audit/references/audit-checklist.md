# 审计维度与证据线索

`full` 考虑全部维度，其他模式只深入相关部分。下表用于发现证据缺口，不是工具采购清单或强制架构标准。每个维度记录已查 / 部分 / 未查 / 不适用及理由；只有可说明实际影响的差距才形成问题。

| 维度 | 关键判断与证据线索 |
| --- | --- |
| 产品目标与功能完整性 | 对照当前需求、验收条件和明确非目标，追踪功能实际入口与可达实现；占位返回、硬编码样例、未接线模块和演示数据是否被误当成功能完成？ |
| 核心业务流程 | 从真实入口覆盖正常、空输入、非法输入、失败、重复请求和状态转换；业务不变量能否被绕过，失败后是否留下部分成功状态？ |
| 仓库结构与依赖 | 文件职责、应用 / 包边界、依赖方向、锁文件与运行版本是否一致？脚本、生成物和第三方代码是否混杂？依赖漏洞需核实版本、可达路径及修复约束，不能只凭扫描告警定性。 |
| 架构、接口与数据流 | 边界是否承担真实职责，公共 Contract 是否稳定，数据和权限归谁所有？追踪实际消费者、循环依赖、跨层访问、配置选路和外部 Adapter；不因未采用某架构模式就判错。 |
| 代码正确性与可维护性 | 分支、类型 / 空值、资源生命周期、边界条件和副作用是否符合 Contract？复杂度是否带来真实理解或修改成本？文件长度只作线索，不作缺陷证据。 |
| 数据库与一致性 | 模型、约束、索引、迁移顺序和兼容性是否支持实际查询与升级？事务范围、幂等、隔离、并发写入、回滚和备份恢复是否满足数据风险；不运行真实迁移来“验证”。 |
| 安全与身份权限 | 认证、授权、租户 / 数据隔离是否在可信边界执行？检查注入、路径 / 文件访问、SSRF、上传、依赖、密钥及日志泄漏；结合攻击入口、部署暴露面与已有防护确认可达性，不运行未授权攻击。 |
| 可靠性与恢复 | 超时是否贯穿调用链，重试是否有上限并避免重复副作用？检查并发、取消、锁、队列、背压、资源耗尽、部分失败及恢复，按项目负载判断必要性。 |
| 测试与评测 | 单元、集成、Mock、E2E 是否验证关键公共行为、失败和边界？检查跳过项、空断言、过度 Mock、脆弱交互断言、测试隔离和运行入口；覆盖率不等于功能正确。重复测试是否覆盖不同风险，删除会丢失什么独有信号？ |
| CI/CD、配置与部署 | CI 实际运行哪些检查，是否与本地命令一致？追踪构建产物、容器、配置优先级、初始化、健康检查、迁移及回滚链路；区分配置存在、历史成功和本次部署验证，不强制小项目使用容器或复杂流水线。 |
| 日志、Trace、审计与可观测性 | 核心故障是否能定位到请求、步骤和外部依赖？敏感操作是否有必要的审计记录，日志是否泄漏秘密？按故障排查和合规的实际需求判断，不默认必须建设 Trace 平台。 |
| 文档与实现漂移 | README、Spec、ADR、示例、环境变量、命令和实际代码是否一致？声明的支持范围是否经过相应链路验证？文档遗漏的影响是否足以阻塞使用或维护？ |
| 冗余与过度工程 | 识别重复入口、脚本、实现、闲置依赖、废弃代码、透传层、无替换需求的抽象和无价值重复检查。追踪运行时注册、反射、插件发现、外部消费者、打包入口和兼容承诺，不能用一次文本搜索宣布死代码。 |
| AI 专项（适用时） | 按下节追踪 Prompt → 检索 / 模型 → 工具 / 数据 → 输出 → Evaluation 的真实链路，区分确定性软件验证与模型行为评测。 |

## 冗余候选的判断

对每组候选记录：真实职责和变化原因、所有已知调用方与入口、独有行为 / 风险覆盖、维护成本、保留 / 合并 / 删除 / 延期方案、简化收益、兼容和删除风险、验证方式及证据限制。

“代码相似”“仅一个调用方”“存在接口”“测试重复执行”均不能单独证明冗余。兼容入口、平台差异、业务隔离、不同测试层的独有信号可能值得保留。没有现实成本时建议保持现状；无法排除动态或外部调用时标为疑似，禁止建议直接删除。

## AI 项目的专项追踪

- **Prompt**：实际使用哪个版本，变量如何注入，优先级与信任边界是否明确？来自用户、检索和工具输出的 Prompt Injection 能否跨越权限边界？
- **RAG**：索引来源、更新 / 删除、租户过滤、检索与重排是否一致；空检索、陈旧数据、引用来源和回答证据是否有处理？
- **Agent / Tool Calling**：工具参数是否校验、权限是否在服务端执行、危险操作是否授权；循环是否有终止、调用预算、超时、重试和幂等控制？
- **结构化输出**：Schema、解析、业务校验、拒绝 / 截断 / 非法输出及回退是否闭环；模型声称的成功是否与真实工具结果一致？
- **SQL 安全**：可信权限边界、数据范围、参数化 / AST 校验、只读账号、查询预算和结果脱敏是否满足风险？不能仅依赖 Prompt 约束危险 SQL。
- **LLM Evaluation**：数据集是否代表目标任务及失败场景，是否隔离评测泄漏；指标、判分、版本、基线和阈值是否有依据？区分 Mock、回放、历史真实模型结果和本次真实评测，不默认强制新建评测平台。
- **模型成本与可靠性**：结合配置或脱敏历史记录核对模型、Token、延迟、并发、限流、上下文上限、预算和降级；没有测量时明确未验证，不能凭估计声称满足成本或质量目标。真实模型调用仍须预先明确授权。
