# Phase 边界

一个 Phase 是一次会话中的一段完整工作，例如需求澄清、Spec、Ticket 或实现。默认优先继续当前上下文，因为设计原因、用户决策和失败尝试通常不能由摘要完全恢复。

按以下顺序处理：

1. 下一阶段需要当前完整推理、术语和决策时，继续当前上下文；
2. 当前上下文已经与下一阶段无关且没有需要保留的决策时，才清理；
3. 切换目录、工具或交给其他人时，才写 handoff；
4. 默认不调用独立 Agent。只有用户和项目规则明确允许，并且任务确实独立时，才考虑 Subagent；
5. 仍然相关但上下文接近上限时，才压缩，并明确保留事实、决策、边界和下一步。

Phase 切换和 Skill 隐式调用都不等于权限提升。主 Agent 可在用户目标要求继续且当前阶段 Done When 已满足时调用下一阶段 Skill，不要求用户逐个手动触发；每个阶段仍须满足 Spec、Ticket、关键决定、实施和发布各自的确认门禁。用户只要求探索、澄清或撰写 Spec 时，到该请求范围为止，不自动扩大到实施。
