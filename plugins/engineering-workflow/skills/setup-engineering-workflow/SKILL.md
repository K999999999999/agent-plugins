# 初始化当前仓库的工程工作流

这是一个需要用户明确手动调用、通常每个仓库执行一次的初始化 Skill。Plugin 安装后、每次启动工程工作流时，都不得自动运行本 Skill。

目标是让工程工作流遵循当前仓库自己的约定，不是把某个固定目录、Tracker、Spec 模板或 ADR 结构复制到所有仓库。

## 1. 探索仓库现状

只读检查并报告证据：

- `AGENTS.md`、`CLAUDE.md` 以及其他仓库或目录级 Agent instructions；
- README、贡献指南、工程规范和现有 Agent / Skill 配置；
- 现有 Spec、Ticket、Issue、需求记录和其状态约定；
- ADR、Architecture、Domain、Context 文档及其实际位置；
- monorepo、多个应用或多个领域上下文等会影响约定的结构；
- 相关目录中的样例文件，用以判断实际使用的命名、模板和生命周期。

参考 [工作项约定发现](issue-tracker-local.md) 和 [领域文档约定发现](domain.md) 作为检查清单。它们是发现方法，不是要求仓库采用的模板。

区分当前已确认规则、实际观察到的用法、彼此冲突的规则和仍未明确的部分。不得仅因某个常见文件或目录不存在，就判定仓库需要新增它。

## 2. 提出最小方案并等待确认

向用户报告：

- 已发现的规则和事实源；
- 哪些现有约定可以直接复用；
- 是否存在冲突或 monorepo / 多上下文归属问题；
- 准备新增或修改的每个文件、具体内容及理由；
- 明确不需要变更的部分。

如果现有约定已经足够，说明无需初始化，不创建文件。

如果缺少必要约定，先根据该仓库结构提出适配方案。可讨论 Spec、Ticket、领域文档、ADR 和 Agent instructions 各自放在哪里，但不得预先选定固定目录或状态集合。等待用户确认方案及文件清单；未确认前不写入。

## 3. 按确认范围写入

用户确认后：

- 只修改确认过的文件和内容；
- 优先原位补充已有规则，不覆盖周边内容或其他 Agent instructions；
- 沿用仓库已经在用的路径、名称、格式和状态；
- 如果执行时发现计划与实际文件冲突，暂停并向用户说明；
- 不擅自创建空的 Spec、Ticket、ADR、Domain 文档或目录；
- 不设置外部 Issue / PR 流程，不修改代码、测试、数据库、远程仓库或凭证。

## 4. 完成报告

列出仓库实际采用的约定、创建或修改的文件、保留的既有规则和仍未解决的问题。说明后续工程工作流会读取这些仓库事实；除非用户要求，不重复初始化。

默认使用中文。Skill 名称、命令名、API、类名、函数名、文件路径、代码和必要的原始术语保持原样。
